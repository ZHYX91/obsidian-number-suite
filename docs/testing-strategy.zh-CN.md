# Number Suite — 测试策略

[English synced translation](testing-strategy.en.md)

<!-- section: authority -->
## 文档权威性

本文是验证层级、准入门槛和证据声明规则的中文规范源，英文文件为同步译本。
`ACCEPTANCE.md` 是可执行清单，不能降低本文要求。

<!-- section: evidence-levels -->
## 证据层级

1. **源码检查**：format、双语结构、lint、类型、纯逻辑和适配层测试。
2. **候选包检查**：生产 bundle、manifest/版本一致性、external、离线运行时和精确资产布局。
3. **宿主验收**：指定 Obsidian 版本、操作系统、主题和隔离 Vault 中的实际交互。
4. **设备验收**：模拟器与实体设备分别记录；一个不能替代另一个。
5. **公开发布**：远端 tag、Release 资产、字节比较和 provenance；本地构建不能证明这一层。

报告必须说明证据属于哪一层，不得用较低层推导较高层通过。

<!-- section: automated-tests -->
## 自动测试

核心测试覆盖扫描器、模板编译、数字格式、前缀识别、排除、计数、设置清洗、不可变变更计划、
题注解析、独立题注计数、脚注/尾注语法、独立笔记计数、重复引用和定义容器保护。应用层测试
覆盖虚拟/隐藏计划、失败关闭的同文件引用与笔记解析、独立题注对齐、基于选择范围的注释源码
展开、Properties 解析、当前笔记覆盖和并发条件替换。适配层测试覆盖恢复数据、阅读视图 DOM
数量校验、语义标记清理和设置合约。纯逻辑侧栏大纲投影覆盖 H1-H9 层级、题注、显示标签、
受保护区域和块 ID 去除；当前笔记定向测试覆盖侧栏焦点和重复视图失败关闭。扩大
识别范围前必须添加误报样例。

覆盖率阈值是回归下限，不是质量目标或宿主通过证明。新增关键分支必须有行为断言，即使总
覆盖率仍高于阈值。

<!-- section: canonical-gate -->
## 标准门禁

在仓库固定的 Node.js `24.19.0` 和 npm `11.17.0` 下执行：

```bash
npm ci
npm run check
```

标准门禁依次验证运行时合约、真实格式检查、README 双语结构、五对稳定文档、lint、严格
TypeScript、带阈值的覆盖率、生产 bundle 和发布资产契约。`release:check` 在此基础上增加
版本/tag/干净工作树检查。

<!-- section: host-acceptance -->
## 宿主验收

首次运行必须使用隔离验收 Vault。至少验证由功能区打开的侧栏、两个内部选项卡、H1-H9 与
题注大纲跳转、当前笔记控制、独立显示/隐藏、实时预览、阅读
视图、预览写入与撤销、来源可访问性、插件禁用清理、同长度编辑、Properties 持久化和链接
风险提示。批处理还需验证预览过期、并发冲突、中途失败、恢复和排除文件夹。

IME、移动端、弹出窗口、第三方主题和超长文档延迟必须使用真实宿主环境，自动 DOM 测试不能
代替。详细步骤保留在[运行时清单](ACCEPTANCE.md)。

Android 15 / API 35 独立模拟器是每个移动端候选的基准设备门禁，必须安装并核对最终候选字节，
完成侧栏开关、两个选项卡、H1-H9 与题注大纲跳转、44 像素触摸目标、当前笔记控制、实时
预览、阅读视图、中文输入法、写入/清理往返、七页设置、前后台切换和停用清理。实体 Android
是独立增强证据，不是 Number Suite 的基准移动门禁；重大触摸、
输入法、存储或平台边界风险可以补充执行，但不能升级为插件专属发布前置条件。缺失时
必须报告为未验证，不得从模拟器结果推断真机通过。iOS 不在当前验收矩阵内，也不得从 Android
结果推断。

0.7 系列还必须验证四种题注关键词在有无 ID 时的行为、逐文件独立计数、显式标题/块引用及
别名、普通链接不受影响、目标缺失或重复时失败关闭、独立对齐开关、嵌入文件边界和 Markdown
字节不变。
脚注/尾注验收还必须覆盖默认、显式、尾注及历史语法，按类型独立计数、重复引用复用编号、
缺失/重复/规范化冲突失败关闭、两空格续行保护、渲染节点数量不匹配保持原样，以及 Markdown
字节不变。Live Preview 还需验证 `1` 与 `E1`、原始标记模式、点击/光标展开，以及阅读模式
跳转保持不变。触控与输入法回归还必须确认只显露当前标题、题注或引用的源码，其他虚拟装饰
继续显示。

<!-- section: records -->
## 验收记录

每条记录包含候选提交、资产 SHA-256、插件/Obsidian 版本、操作系统或设备、Vault 类型、主题、
自动门禁结果、实际通过案例、已知限制、日期和执行者。记录是追加式历史事实；后续代码或文档
不得反向把旧候选描述为新候选已验收。

<!-- section: release-decision -->
## 发布判定

只有目标版本的标准门禁、候选包契约和计划声明所需的宿主矩阵均具备时，才可宣称相应范围
通过。缺少 macOS、Linux 或实体移动设备记录时，应明确限制，而不是使用“跨平台已验证”。
Android 支持声明至少要求当前候选的 API 35 模拟器证据；实体 Android 状态单独报告。
是否发布及远端资产验证见[发布策略](release.zh-CN.md)。
