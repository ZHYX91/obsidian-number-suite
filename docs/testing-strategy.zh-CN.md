# Number Suite — 测试策略

[English synced translation](testing-strategy.en.md)

<!-- section: authority -->
## 文档权威性

本文是验证层级、准入门槛和证据声明规则的中文规范源，英文文件为同步译本。
`ACCEPTANCE.md` 是可执行清单，不能降低本文要求。

题注回归在实际计划与确认后的编辑器事务之后断言块 ID 归属、题注与对象关联不变量。固定样本 `tests/fixtures/structural-table-source-contract.json` 与提供方仓库保持一致，各项目使用仓库内的副本驱动真实解析器/生产者或消费者。无表头、短分隔符、同文双表、外部 ID、UTF-16/CRLF 偏移和引用容器覆盖双方识别范围不一致的边界。消费者拒绝不完整、未知、过期和错误路径快照；确认阶段拒绝变化的源码或文件。测试不联网拉取另一仓库，也不依赖其运行时。
对象带有额外块 ID 时，四类题注在 LF 与 CRLF 下均应拒绝迁移。迁移会跳过原文内容时，核心计划
以及源码和 Structural Tables 两个菜单入口必须保持原始字节，不能产生编辑器事务。

<!-- section: evidence-levels -->
## 证据层级

1. **源码检查**：format、双语结构、lint、类型、纯逻辑和适配层测试。
2. **候选包检查**：生产 bundle、manifest/版本一致性、external、离线运行时和精确资产布局。
3. **宿主验收**：指定 Obsidian 版本、操作系统、主题和隔离 Vault 中的实际交互。
4. **设备验收**：Android 模拟器是支持的移动验收表面；Android 真机和 iOS 不在验收范围内。
5. **公开发布**：远端 tag、Release 资产、字节比较和 provenance；本地构建不能证明这一层。

报告必须说明证据属于哪一层，不得用较低层推导较高层通过。

<!-- section: automated-tests -->
## 自动测试

真实 Lezer 与生产消费端回归覆盖根级/容器缩进代码、合法四空格或 Tab 段落续行、完成块与空行边界、CRLF/CR 和 Unicode 偏移。断言最终脚注首次引用编号、显示计划及互操作导出，保留 Code 题注的围栏起始绑定与 Obsidian 注释内的围栏近似文本。规模回归把 8 组标题/题注扩大到 400 组，要求真实 Markdown 解析次数不随目标数增长，并核对全部目标 ID、引用和重复 ID 歧义；这不证明宿主速度或呈现通过。

核心测试覆盖扫描器、模板编译、数字格式、前缀识别、排除、计数、设置清洗、不可变变更计划、
题注解析、独立题注计数、脚注/尾注语法、独立笔记计数、重复引用和定义容器保护。应用层测试
覆盖虚拟/隐藏计划、失败关闭的同文件引用与笔记解析、独立题注对齐、基于选择范围的注释源码
展开、Properties 解析、当前笔记覆盖和并发条件替换。适配层测试覆盖恢复数据、阅读视图 DOM
数量校验、语义标记清理和设置合约。纯逻辑侧栏大纲投影覆盖 H1-H9 层级、题注、显示标签、
受保护区域和块 ID 去除；当前笔记定向测试覆盖侧栏焦点和重复视图失败关闭。扩大
识别范围前必须添加误报样例。

容器契约使用真实解析器与标题计划处理列表、引用块、嵌套围栏和 HTML 样例，断言保护区字节
不变、修改范围不越界、后续正文标题的编号正确，以及普通正文引用继续可用。覆盖 LF、CRLF、CR、
容器内未闭合围栏及 H7-H9 边界。预期结果来自文档契约，不使用实现中的容器分类器生成期望值。
已经打开的注释必须能跨被跳过的字面量行正常结束，代码示例中的新注释起始符和引用不能激活；
注释前后的普通正文引用保持可用。

覆盖率阈值是回归下限，不是质量目标或宿主通过证明。新增关键分支必须有行为断言，即使总
覆盖率仍高于阈值。

批处理生命周期测试暂停 pending 恢复记录保存、条件写入回调及已接受写入，验证卸载后不再进行下一次正向写入、精确补偿、保留并发编辑和恢复记录、静默结算，以及立即重新启用后的归属。DOM 测试覆盖逐文件展开、分页、折叠、不会切断 Unicode 码点的前缀差异，以及现场说明对 Properties 和标题改写的区分。组件截图和合成浏览器计时不等于真实 Obsidian、Android、原生输入法或读屏器验收。

批处理预览测试使用生产计划器与确认回调，在读取期间、预览之后及清理范围变化之后替换或重命名文件；即使路径与正文相同，也必须对替身文件零写入。计数器测试覆盖安全整数边界、依赖计数的模板引用、显示省略，以及溢出时保持原文的写入/重新编号计划；清理仍可独立使用。

<!-- section: canonical-gate -->
## 标准门禁

在仓库固定的 Node.js `24.19.0` 和 npm `11.17.0` 下执行：

```bash
npm ci
npm run check
```

标准门禁依次验证运行时合约、真实格式检查、README 双语结构、现有产品文档的翻译一致性、lint、严格
TypeScript、带阈值的覆盖率、生产 bundle 和发布资产契约。`release:check` 在此基础上增加
版本/tag/干净工作树检查。

<!-- section: host-acceptance -->
## 宿主验收

按改动影响选择精确候选的代表性验收；桌面交互、设置或生命周期变化覆盖相关真实宿主场景，移动交互或影响移动端的共享运行行为变化覆盖相关 Android 模拟器场景。纯文档或无宿主影响的逻辑改动可记录理由后免宿主。影响本次发布的已确认严重产品缺陷应阻塞对应发布；宿主或工具缺项保留未验范围，按风险判断是否延后，不自动阻塞所有发布，也不增加一律再次确认的步骤。只有实际观察通过的范围可声称已验收。完整宿主矩阵不是每次发布的前提，CI 不自动检查宿主覆盖。使用所选宿主时，使用隔离验收 Vault，按改动范围验证由功能区打开的侧栏、两个内部选项卡、H1-H9 与
题注大纲跳转、当前笔记控制、独立显示/隐藏、实时预览、阅读
视图、预览写入与撤销、来源可访问性、插件禁用清理、同长度编辑、Properties 持久化和链接
风险提示。批处理还需验证预览过期、并发冲突、中途失败、恢复和排除文件夹。

IME、移动端、弹出窗口、第三方主题和超长文档延迟必须使用真实宿主环境，自动 DOM 测试不能
代替。详细步骤保留在[运行时清单](ACCEPTANCE.md)。

选择移动端验收时，使用 Android 15 / API 35 独立模拟器，安装并核对最终候选字节，
完成侧栏开关、两个选项卡、H1-H9 与题注大纲跳转、44 像素触摸目标、当前笔记控制、实时
预览、阅读视图、中文输入法、写入/清理往返、七页设置、前后台切换和停用清理。Android 真机
和 iOS 不在当前验收矩阵内；该模拟器是 Number Suite 的完整移动验收表面。

题注与引用验收还需验证四种题注关键词在有无 ID 时的行为、逐文件独立计数、显式标题/块引用及
别名、普通链接不受影响、目标缺失或重复时失败关闭、独立对齐开关、嵌入文件边界和 Markdown
字节不变。
脚注/尾注验收还必须覆盖默认、显式脚注和尾注语法，按类型独立计数、重复引用复用编号、
缺失/重复/规范化冲突失败关闭、两空格续行保护、渲染节点数量不匹配保持原样，以及 Markdown
字节不变。Live Preview 还需验证 `1` 与 `E1`、原始标记模式、点击/光标展开，以及阅读模式
跳转保持不变。触控与输入法回归还必须确认只显露当前标题、题注或引用的源码，其他虚拟装饰
继续显示。

<!-- section: records -->
## 验收记录

每条记录包含候选提交、资产 SHA-256、插件/Obsidian 版本、操作系统或设备、Vault 类型、主题、
自动门禁结果、实际通过案例、已知限制、日期和执行者。记录是追加式历史事实；后续代码或文档
不得反向把旧候选描述为新候选已验收。

<!-- section: release-decision -->
## 发布判定

只有目标版本的标准门禁、候选包契约和计划声明所需的宿主矩阵均具备时，才可宣称相应范围
通过。缺少 macOS 或 Linux 记录时，应明确限制，而不是使用“跨平台已验证”。Android 支持
声明至少要求当前候选的 API 35 模拟器证据；Android 真机和 iOS 不在验收范围内。
公开发布需要单独授权，远端资产由本仓库工作流验证。
