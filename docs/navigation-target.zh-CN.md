# Number Suite — 导航与结构编辑目标

[English synced translation](navigation-target.md) · [文档目录](README.md)

<!-- section: authority -->
## 范围与状态

本文记录已批准的导航方向和默认值，不表示所有功能已经实现或通过宿主验收。
本文为中文规范源，英文为同步译本。各功能落地时，应同步修订产品需求、交互规范、架构、
测试与使用说明中相应的现有规则，避免让目标文档与当前行为长期并存为两套权威说明。
实现状态、候选身份、执行记录和缺失的验收证据写在对应 PR，不写入本文。

最终分工为：增强后的原生大纲负责紧凑的日常导航；独立标题思维导图负责图形化结构浏览，
并分阶段增加结构编辑；Number Suite 侧栏负责当前笔记配置、诊断及明确的编号文件操作。
自有 Document outline 仅作为迁移期功能保留，不再以完整复制原生大纲为长期目标。

## 默认值与持久化

| 功能 | 新安装或缺失设置时 | 范围 |
| --- | --- | --- |
| 增强普通同文件 Wiki 章节链接 | 关闭 | 只增强可靠解析到当前笔记标题的普通 Wiki 链接 |
| 原生大纲显示编号 | 开启 | 使用当前笔记有效的编号显示结果 |
| 原生大纲显示 7–9 级标题 | 开启 | 将有效扩展标题加入该笔记的大纲 |
| 原生大纲显示题注 | 开启 | 显示图、表、公式、代码题注导航项 |
| 标题思维导图入口 | 可见 | 提供入口，不自动打开导图 |

必须分别持久化各项选择。明确保存的 false 不是缺失值；升级、重载与恢复工作区都不得把
用户已经关闭的功能重新开启。不得将“其他都是开”扩展为修改已有无关默认值，例如正文虚拟
编号、来源标记、源码模式或文件写入行为。仍尊重笔记级退出及既有编号规则。

“大纲增强”是全局设置中的一个独立选项卡，包含上述三个大纲开关；不另加重复总开关。
普通 Wiki 链接开关放在“交叉引用”，而不是大纲设置中。所有可见开关必须有实际生效、
即时刷新、保存失败提示和关闭恢复路径，不交付只有界面或持久化字段的空开关。

默认开启不意味着静默启用核心“大纲”插件、打开或移动窗格、创建 Properties 或改写笔记。
原生大纲未启用或适配不可用时说明原因，保留独立导图命令及当前笔记入口。
普通 Wiki 链接增强虽默认关闭，设置说明与一次性的功能介绍应让用户能够发现它，
不使用重复弹窗或常驻提醒。

## 引用的显示与编辑

已渲染的显式 `@[[...]]` 引用应单击完成导航；不要求先展开源码、移出光标再点一次。
通过键盘把文本插入光标移入引用时，恢复当前引用的完整源码；已进入源码编辑后，普通点击
用于定位光标，不强行跳转。选择、输入法组合输入、上下文菜单与周围文本拖选不能被破坏。
离开编辑范围后恢复显示。前后边界的具体手感须与宿主对照，不把鼠标悬停误认为插入光标进入。
应提供可发现的源码编辑入口；移动端不能只依赖桌面方向键或修饰键。

普通 Wiki 标题链接增强是独立的显示投影，不把普通链接加入显式语义引用的导出协议。
关闭时所有普通链接完全保持原生行为；开启时支持 `[[#标题]]` 和可靠解析到当前文件的
`[[当前文件#标题]]`，保留 `[[#标题|别名]]` 的别名。判断同文件必须依据真实目标文件身份，
不能按文件名后缀、活动窗格或字符串是否以 `[[#` 开头猜测。

显示编号来自目标标题在当前笔记的有效显示结果，不产生另一套编号。标题目标或其源位置
不能可靠确定、目标没有有效编号、目标失效或有歧义时，保持普通链接的原生显示和跳转。
不得把原生路径解析替换为更宽松的标题匹配。代码、注释、公式、链接元数据等受保护范围
继续使用现有保护规则；不得破坏相邻文本、UTF-16 位置或别名。

跨文件章节链接继续交给原生处理，不附加编号。普通块链接、嵌入和标准 Markdown 链接
不因该开关被一并接管。跨文件编号属于另行设计的范围；即使将来支持，也必须使用目标
笔记的有效编号，而不是当前笔记的方案。现有显式引用继续支持既有标题、题注和块 ID 规则。

## 原生大纲增强

使用已有文档解析和编号结果提供视图级适配，不在原生面板里覆盖一棵自有树，不为显示题注
污染整个应用共享的标题索引，不写 Markdown。H7–H9 在大纲中可导航，不等于原生链接、
反链或其他插件也获得扩展标题支持。

编号必须绑定文件、源位置与当前文本身份。搜索、折叠、重名标题、跳级和暂时过期的缓存
不能导致编号错配；不能按当前可见行的序号配号。保留原生不属于插件编号范围的标题项。
不重复添加已有实体编号，不强制开启正文编号，不越过笔记级禁用；配置无效时保留普通
原生导航，不伪造附加编号。

H7–H9 按已有精确扩展规则识别，保留真实层级和源位置。题注是所属章节下的导航项，
不是新章节、编号计数器或后续标题的父项。关闭任一大纲开关不改变正文、导图或导出语义；
全部关闭时原生条目显示恢复原样。

普通标题的原生搜索、折叠、定位、跟随、预览及章节重排不得被增强破坏。新增条目不能
无条件继承修改正文的操作：没有可靠实现与验收前，扩展标题和题注作为导航项，禁止不安全
的拖动及落点。普通章节移动时必须保持其完整正文范围，不能因合成题注改变章节边界。
按虚拟编号搜索和扩展条目的其他原生交互必须单独验证，不能仅因显示成功就宣称全部继承。

适配应检查宿主能力、限制作用范围并可完全撤销。关闭、重载或卸载后清理本插件的节点、
事件和包装，不破坏原生或其他插件拥有的对象。部分能力不兼容时只停止受影响的增强并给出
可理解的状态，不使原生大纲失效。避免与其他编号或扩展标题插件重复装饰同一条目。

## 导图入口与侧栏迁移

推荐主入口为原生大纲顶部工具栏，备用入口为当前笔记面板顶部；独立命令与用户已有快捷键
持续可用。按钮可见不依赖三个大纲显示开关，不抢占原生控件，不自动弹出导图，不另建一个
导图选项卡或默认增加独立功能区图标。工具栏无法可靠适配时，其他入口仍然可用。

从面板打开导图时使用该面板实际关联的文件和源窗格，而不是任意当前活动文件；多窗格、
固定或关联面板均须验证。按钮及错误提示复用现有本地化体系，移动端也必须可发现和可操作。

原生增强可靠承接既有导航且入口迁移通过验收后，移除自有 Document outline 及侧栏内部
标签栏，直接展示当前笔记配置、有效值、诊断、写入和清理操作。迁移旧命令与工作区状态，
保留仍供导图、编号和引用使用的公共模型。不在替代功能尚未可用时删除唯一的 H7–H9 或
题注导航入口，也不以此为由长期并行开发两套完整大纲。

## 导图结构编辑

第一阶段只增加同文件、同一父节点下的章节排序；移动完整标题子树与正文，标题级别保持
不变。后续阶段再处理跨父节点移动和层级调整，保留子树相对级别，拒绝越过 H9、循环父子
关系及不可确认的目标。导图仍以标题为结构节点，不把题注变成子标题。

推荐明确区分浏览与“调整结构”模式。浏览状态下现有平移、缩放、选择、折叠和导航手势
不变；进入结构编辑后，以清楚的落点预览表达修改意图。取消、无效落点、只读或过期源文本
不写入。结构编辑模式下同时提供可键盘聚焦、触摸点击的“上移／下移”同级章节操作，和拖放共用源文本核对及撤销机制，不能将鼠标拖拽作为唯一的操作入口。触摸平移、捏合、长按和结构拖动不能相互误触发；具体启动手势需要宿主验证。

一次结构修改使用不可变的有界计划，在提交前核对文件、编辑器和源文本；拖放预览作为
此专用模式的可见操作预览，并在相关写入契约中明确这一变体。一次成功拖动对应一次完整
撤销与重做；单独打开导图也不能缺少撤销。不能仅以模式开关替代源文本验证或恢复能力。

优先移动原文区间，保留正文、代码、表格、图片、块 ID、脚注、换行和未参与变更的文本。
跨章节的题注/对象绑定、重复标题及嵌套标题路径需要专门检查，不保证所有既有链接天然不受
影响，不猜测重写全库链接。虚拟编号在移动后刷新，已写入正文的编号原样随章节移动；
实际重新编号仍是独立的预览与确认操作。

## 功能验收

| 领域 | 必须覆盖的行为 |
| --- | --- |
| 默认值与保存 | 新安装、旧数据缺字段、明确 true/false、保存失败/重试、重载、笔记级退出 |
| 引用 | 首次点击、别名、键盘入内/退出、源码模式、拖选、IME、触摸与长按、失效/歧义、跨文件原生对照 |
| 大纲 | 三开关八种组合、编号一致性、已有实体编号、重复/跳级标题、过滤折叠、题注父项、空笔记、配置错误 |
| 宿主生命周期 | 最低支持版本和当前版本、多窗格、切换笔记、原生大纲关闭/重开、插件重载/卸载、冲突插件、长文档 |
| 结构修改 | 精确前后文本、完整撤销/重做、脏编辑器、多窗格和外部编辑冲突、取消、题注对象边界、只读拒绝 |

纯逻辑、模拟 DOM、实际浏览器、打包产物和真实 Obsidian 行为是不同证据。不能用构建成功或
浏览器夹具替代桌面与 Android 宿主验收，不能把未执行的测试写成通过。每个功能的文案和
使用说明必须区分已实现行为与尚未验证的能力。

## 交付边界

引用交互、普通同文件 Wiki 增强、原生大纲增强、旧界面迁移和导图结构编辑可分别交付，
不必绑定同一个版本。旧大纲的移除不等待所有导图编辑功能，但必须等待导航替代与入口迁移
通过验收。默认值必须随对应的真实功能一起交付，不能用一批空开关代替功能实现。

此目标不授权合并、发布、打标签、部署到实际 Vault、修改版本、持久化协议或互操作协议。
源码与功能验证独立于托管 CI 是否为绿色；不为追逐 CI 状态修改无关工作流、门槛或依赖，
也不以“不看 CI”为理由跳过与功能直接相关的回归、数据保全或宿主检查。
