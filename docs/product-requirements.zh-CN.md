# Number Suite — 产品需求

[English synced translation](product-requirements.en.md)

<!-- section: authority -->
## 文档权威性

本文是 Number Suite 产品需求的中文规范源。英文文件是同步译本。实现、测试或其他文档与
本文冲突时，应先更新中文规范源、评审差异，再同步英文；执行证据不能修改产品要求。

<!-- section: purpose -->
## 产品目的

Number Suite 让用户分别控制“标题序号是否写入 Markdown”和“标题序号是否在 Obsidian
中可见”。插件必须允许用户保持纯净源文件、保存实体序号、隐藏实体序号或以计算序号替换其
视觉呈现，同时保持所有文件修改可预览、可解释并尽量可恢复。

<!-- section: users-and-jobs -->
## 用户与核心任务

- 只想在 Obsidian 中看到层级序号、但不想污染 Markdown 的用户。
- 需要向其他工具输出带实体序号 Markdown 的用户。
- 已有实体序号，希望临时隐藏或安全清理的用户。
- 需要公文、法律条文或自定义层级格式的用户。
- 需要对当前笔记、文件夹或整个库执行一致操作的用户。

<!-- section: scope -->
## 范围

产品处理顶层原生 ATX H1-H6 标题及精确的 Number Suite/DocWen H7-H9 扩展，并支持实时预览、
阅读视图、当前笔记写入操作、批处理、内置及自定义方案、精确标题排除、按笔记 Properties
覆盖、纯显示题注编号、脚注/尾注编号、同文件
语义交叉引用、Number Suite 自有的 H1-H9 与题注侧栏大纲，以及中英文界面。标题方案、每种题注计数、脚注/尾注计数和引用解析都以单个
Markdown 文件为作用域；嵌入文件仍按自己的源码与设置处理。

<!-- section: functional-requirements -->
## 功能要求

1. 虚拟显示和视觉隐藏不得修改 Markdown。
2. 写入、清理、重新编号和移除来源标记必须先生成不可变预览计划。
3. 虚拟显示、阅读视图和文件修改必须共享同一编号语义。
4. 空 Hn 模板不输出序号，但仍增加计数、重置后代并参与后代模板。
5. 非空 Hn 模板必须包含本层占位符，且不能引用后代层级。
6. 自定义方案修改或删除前的模板必须可用于识别历史插件序号，直至用户明确清除历史。
7. 精确排除不得使用模糊或正则匹配；排除标题不得占用计数。
8. 未触碰的笔记不得被写入插件 Properties；恢复继承必须删除相应属性。
9. 只有顶层 `Figure:`、`Table:`、`Equation:` 和 `Code:` 段落声明题注；不兼容
    `Listing:`。四种类型在每个 Markdown 文件内分别从 1 开始，无论是否存在块 ID 都编号，
    显示路径不得写入实体题注编号。无论编号是否开启，识别出的整条题注都使用实心胶囊。
    四种固定类型分别具有独立居中开关，题注编号关闭时仍可
    生效；Figure 和 Equation 默认开启，Table 和 Code 默认关闭并跟随主题。题注类型只决定
    语义标签和编号，不限制承载对象类型；任意题注可绑定一个相邻的独立图片、表格、块公式或
    围栏代码块。零或一个空行允许绑定，两个空行解除绑定；题注或对象存在多个候选时失败关闭。
    未绑定声明仍是题注。四种类型还可分别显示在绑定对象上方或下方，默认均在上方且不改写
    源码；对象锚点提供统一的紧凑视觉间距。图片/Figure 悬停提示默认开启，
    将渲染图题与有效替换文字分开显示，并去重、排除尺寸值和仅文件名噪声。
10. 只有显式 `@[[#目标]]`、`@[[#^块ID]]` 及其可选 Obsidian 别名请求同文件语义增强。
    目标可以是唯一标题名，也可以是 `Figure: 系统架构` 这样的唯一完整类型化题注名。标题名
    和题注名共同消歧；零个或多个匹配都失败关闭。可见编号存在时带上编号，但编号不是前提。
11. 显示路径和题注创建不得创建或改写 ID。只有显式的**复制交叉引用**右键操作可以复用
    目标已有块 ID，或在精确预览和源码过期校验后，用一次编辑器事务在目标合法 Markdown 位置
    创建块 ID。题注 ID 位于题注行末；标题 ID 可以使用下一行独立块 ID。
    后续编辑造成歧义时，不迁移或自动改写已有题名引用。
12. `[^id]` 和 `[^footnote:id]` 声明脚注，`[^endnote:id]` 声明尾注。脚注与尾注在每个
    Markdown 文件内分别从 1 开始，按首次引用顺序编号，重复引用复用首次编号。脚注显示
    纯数字，尾注显示 `E` 前缀。
13. 脚注/尾注显示不得创建、重命名或重写定义、引用、ID 或其他 Markdown。缺失定义、重复
    定义、默认与显式脚注的规范化 ID 冲突，以及源码与渲染结果数量不一致时均失败关闭。定义
    的两空格或 Tab 缩进续行属于受保护容器，不得被扫描为标题、题注或语义引用。Live Preview
    可显示格式化编号或原始标记；单击格式化编号或把光标移到编号处会展开可编辑标记，阅读
    模式保留原生跳转。
14. H7-H9 只识别顶层、行首精确 7、8 或 9 个井号且随后有空白的源码行；10 个及以上井号
    仍是普通文本。扩展标题共用九级解析、计数器、模板、Properties 起始值、变换和
    `number-suite.interop.v2` 语义。已有六项模板的自定义方案升级后 H7-H9 保持为空。
    不承诺 Obsidian 原生大纲、反向链接、标题路径导航或其他宿主标题索引能识别扩展层级；
    互通目标建议使用用户已有的稳定块 ID。
15. 功能区图标打开常驻右侧栏，侧栏含“文档大纲”和“当前笔记”两个选项卡。大纲跟随活动
    Markdown 文件，嵌套显示 H1-H9 与固定题注，使用当前最终生效的 Number Suite 显示标签，
    支持折叠和源码行跳转，并且从不修改 Markdown。“当前笔记”发起的 Markdown 修改仍必须
    经过既有预览和源码过期校验。
16. 编辑器右键菜单只为独占一行的图片嵌入、顶层 Markdown 表格、独立块公式和顶层围栏代码块
    提供题名插入。Figure、Table、Equation、Code 题注统一存放在对象上方；紧邻图片下方的旧
    Figure 题注提供有界迁移。真实右键目标优先于编辑器光标；行内及单元格内图片、公式、代码
    不得成为独立题注目标。Structural Tables 接管的 Live Preview 渲染表格通过
    自己的菜单提供同一操作，并用公开的源码表格序号映射回完整 Markdown 范围，不能确定映射时
    失败关闭。相邻关键词仅大小写错误时修正原行而不重复插入。
    每次操作都必须经过题名预览、不可变有界计划、精确源码复核和一次编辑器事务；不支持、
    受保护、已过期、有歧义或已经有题注的目标均失败关闭；任意语义类型的相邻题注都表示该
    承载对象已有题注。
17. 标题虚拟序号使用紧凑实心胶囊，整条题注使用可换行实心胶囊，增强后的交叉引用使用可
    键盘聚焦的交互式描边胶囊；目标与引用同时通过填充和边框区分，而不是只依赖颜色。

<!-- section: safety-requirements -->
## 安全要求

- 对小数、版本、年份、日期和单位数量等歧义前缀默认失败关闭。
- 写入不得静默覆盖未确认的人工序号。
- 当前笔记确认前必须复核文件、视图和预览源内容。
- 批处理必须复核全部目标内容、保存有界恢复数据，并在并发冲突时停止而不是覆盖。
- 来源标记必须默认关闭，并提供保留可见序号的移除路径。
- 插件不得包含联网、遥测、广告或远程资源。
- 实体标题变化可能破坏标题链接；插件必须提示风险，不得猜测重写链接。

<!-- section: non-goals -->
## 非目标

- 不支持正文内局部方案切换，也不支持已冻结 H7-H9、题注、脚注/尾注和显式语义引用声明
  之外的用户自定义控制语法。
- 不自动重写标题链接、嵌入或外部锚点。
- 不解析跨文件语义引用。
- 不承诺 Setext、Canvas、Obsidian 内置大纲、Backlinks、Search Results 或 PDF 导出集成；
  插件自有侧栏大纲属于范围内功能。
- 不把自动测试、模拟器记录或构建成功表述为所有宿主平台验收。

<!-- section: acceptance -->
## 产品验收

每项需求必须有纯逻辑或适配层测试；涉及真实 Obsidian UI、IME、移动端、主题或生命周期的
声明还必须使用精确候选在隔离 Vault 中取得证据。源码检查、候选包检查、宿主验收、实体设备
验收和公开发布状态必须分别判断。详细规则见[测试策略](testing-strategy.zh-CN.md)和
[发布策略](release.zh-CN.md)。
